# Using Chimney Post with OpenMediaVault (OMV)

OMV needs its own MTA (postfix), so the usual `msmtp-mta` setup from the
README breaks it. This guide keeps postfix in place and points it at Chimney
Post instead.

## Why `msmtp-mta` breaks OMV

On Debian, `msmtp-mta` both Provides and Conflicts `mail-transport-agent`, so
`apt install msmtp-mta` removes the running postfix. OMV depends on postfix and
manages `/etc/postfix/main.cf` through its salt states, so removing or
replacing it breaks the web UI.

Do not run `install.sh` with `CHIMNEY_MTA=yes` on OMV, and do not install
`msmtp-mta`. In the default `ask` mode the installer detects postfix's
`sendmail` and skips the msmtp step.

If the web UI is already broken:

```bash
dpkg -l | grep -E 'postfix|openmediavault|msmtp'
sudo apt remove msmtp-mta          # if it still holds the MTA slot
sudo apt install --reinstall postfix
sudo omv-salt deploy run           # regenerate all OMV-managed config
```

## Why not the OMV Notification page

System -> Notification only configures OMV's own mailer. It does not set
postfix's `relayhost`, so cron, apticron and similar tools still try direct
delivery. Symptom in the mail log:

```
relay=none ... status=bounced (Host or domain name not found. Name service error for name=omv.omv ...)
```

`relay=none` means no relayhost is in effect. Check with `postconf relayhost`.

## Why not edit `main.cf`

`/etc/postfix/main.cf` is regenerated by `omv-salt deploy run`, which wipes
manual edits. The salt template ships with the `openmediavault` package and
exposes no `relayhost` setting, so patching the template just gets overwritten
on the next package upgrade. There is no `openmediavault-postfix` plugin to
expose it either.

Instead, leave OMV's files alone and re-apply the one setting from a systemd
timer.

## Setup

Prerequisites: Chimney Post is installed, configured and running, listening on
`127.0.0.1:2525` (the default `[smtp].bind`). Change the port below if you
changed it.

### 0. Prechecks

```bash
systemctl is-active chimney-post
ss -ltn | grep 2525
postconf relayhost        # empty
mailq | tail -1           # ideally an empty queue
```

Clear a stuck queue first with `sudo postsuper -d ALL`.

### 1. Service

```bash
sudo tee /etc/systemd/system/postfix-relayhost.service >/dev/null <<'EOF'
[Unit]
Description=Ensure postfix relays local mail to chimney-post

[Service]
Type=oneshot
ExecCondition=/bin/sh -c '[ "$(postconf -h relayhost)" != "[127.0.0.1]:2525" ]'
ExecStart=/usr/sbin/postconf -e "relayhost = [127.0.0.1]:2525"
ExecStart=/usr/bin/systemctl reload postfix
EOF
```

`ExecCondition` makes every run a no-op once `relayhost` is already correct, so
postfix is only reloaded after salt has reset it.

### 2. Timer

```bash
sudo tee /etc/systemd/system/postfix-relayhost.timer >/dev/null <<'EOF'
[Unit]
Description=Periodically ensure postfix relayhost points at chimney-post

[Timer]
OnBootSec=30s
OnUnitActiveSec=1min

[Install]
WantedBy=timers.target
EOF
```

### 3. Enable and run once

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now postfix-relayhost.timer
sudo systemctl start postfix-relayhost.service
postconf relayhost        # [127.0.0.1]:2525
```

### 4. Test the path

```bash
echo "relay test" | mail -s "omv relay test" root
journalctl -u postfix -n 20 --no-pager       # relay=127.0.0.1[127.0.0.1]:2525, status=sent
journalctl -u chimney-post -n 20 --no-pager  # the message arrives here
```

Without `mail`: `echo -e "Subject: test\n\nbody" | sendmail root`.

### 5. Check it survives salt

```bash
sudo omv-salt deploy run postfix
postconf relayhost        # may be empty briefly
sleep 70; postconf relayhost
```

The timer restores it within a minute.

## Gotchas

- OMV's default notification address `omv@omv.omv` is a placeholder on a
  non-existent domain. Replace it with a real address under System ->
  Notification, otherwise alerts address mail to `omv.omv` and the sender
  shown in Matrix is meaningless.
- With an unresolvable sender or recipient domain and no relayhost, postfix can
  enter a bounce loop that creates a new message every second. If `mailq`
  keeps growing, stop it with `sudo postsuper -d ALL`.
- Because postfix stays the system MTA, this routes all local mail (OMV
  notifications, cron, apticron) through Chimney Post, not only OMV's.
- Tools that hardcode `/usr/sbin/sendmail` also work, since that is still
  postfix. A plain `msmtp` plus a `/usr/local/bin/sendmail` symlink would not
  catch them.
